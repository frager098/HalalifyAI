## 1. How to read this dictionary

| Role | Meaning | May enter the live model? |
| --- | --- | --- |
| ID | Identifies a stock, date or data version | No, unless an explicitly registered future encoding experiment says otherwise. |
| RAW | Evidence obtained from a provider or filing | Only through declared feature calculations. |
| X | Feature available at prediction time | Yes, if present in the model's saved feature list. |
| Y | Future outcome or label | Never. It is an answer for training/evaluation. |
| PRED | Output generated by a fitted model | Output only. |
| SCREEN | Evidence or result used for eligibility rules | Separate screening engine; not a core predictor. |
| META | Provenance, status or version | Controls validation and audit; not an input feature. |

**Priority C:** core forecasting requirement. **Priority S:** screening requirement, needed before eligible portfolio claims. **Priority E:** optional extension, not a blocker for the first model.

The basic unit is one instrument on one US exchange session. Keep fields with different update schedules in different records: prices are daily, filings arrive irregularly, screening runs when evidence changes, and predictions are outputs. Do not overwrite old versions when a new filing or model arrives.

## 2. Global conventions

- Field names: lowercase `snake_case`.
- Dates: `YYYY-MM-DD`, representing the US exchange session when relevant.
- Timestamps: ISO 8601 UTC, with `Z` or an explicit UTC offset. Preserve the exchange timezone in calendar metadata.
- Ratios and returns: decimal fractions. `0.08` means 8%, not 0.08%. Convert only for display.
- Volatility: annualized decimal. `0.25` means annualized volatility of 25%; forecast window remains 20 sessions.
- Prices and monetary amounts: USD for this experiment. Monetary source values are normalized to full currency units, not millions or thousands.
- Compute features in float64. Backend money can use an appropriate exact decimal type such as `DECIMAL(28,8)`; do not round before calculation.
- `null` means absent/unknown/not yet observed. It is not zero, false, compliant or neutral. JSON cannot contain NaN/Infinity; serialize them as null with a reason.
- No backward filling of financial reports or macro observations. No price interpolation or forward filling to manufacture trading sessions.
- Keep numeric zero when it is explicitly observed and valid, such as a confirmed zero dividend on a non-event day.
- Class order: `[low, medium, high]`; optional numeric encoding `[0,1,2]` must be saved with the model.
- Sources of truth: raw snapshot for evidence, this dictionary for transformations, saved label definition for thresholds, and model registry for input order.

## 6. Daily price and action records

### `daily_prices` — priority C

| Field | Type / unit; role | Definition and missing policy |
| --- | --- | --- |
| `dataset_version` | string; META | Required source-snapshot link. |
| `instrument_id` | string; ID | Required instrument/benchmark link. |
| `session_date` | date; ID | Must exist in the chosen calendar. |
| `open` | float64 USD/share; RAW | Provider non-dividend-adjusted session opening price on its documented share basis; >0 when present. |
| `high` | float64 USD/share; RAW | Highest session price on the same OHLC basis; >0 when present. |
| `low` | float64 USD/share; RAW | Lowest session price on the same OHLC basis; >0 when present. |
| `close` | float64 USD/share; RAW | Session closing price, without dividend adjustment, on the documented share basis. It is not assumed historically as-traded without verification. |
| `adjusted_close` | float64 adjusted USD/share; RAW | Validated split/dividend-adjusted close for total-return calculations; >0. Required for core features/targets. |
| `volume` | float64 shares/session; RAW | Reported trading volume on the documented share basis; >=0. Do not assume all providers use the same split treatment. |
| `dividend_per_share` | float64 USD/share; RAW | Provider action amount and convention; 0 only for a confirmed non-event, null if action coverage is unknown. Retained for checks, not added again to adjusted returns. |
| `split_ratio` | float64; RAW | New shares / old shares on action date; 1 for a confirmed non-event. Normalize vendor 0/no-event only with documented coverage. |
| `bar_available_at` | UTC timestamp or null; META | Observed publication/availability timestamp if provided. Historical daily sources may not report one; record the after-close assumption instead of fabricating it. |
| `data_quality_flags` | array of strings; META | Examples: `missing_bar`, `unknown_adjustment`, `unresolved_action`, `zero_volume`, `suspected_bad_tick`. |

Validation: unique `(dataset_version, instrument_id, session_date)`; finite positive prices; `low <= min(open, close)` and `max(open, close) <= high` for complete OHLC; nonnegative volume; no weekend/holiday bars; no unexplained currency changes. Do not compare adjusted close to unadjusted high/low for this inequality.

Preserve genuine large returns. An absolute one-day adjusted return above 0.50 triggers inspection, not automatic deletion or clipping. A zero-volume bar is flagged and investigated; it is not silently replaced. Keep missing sessions in the alignment table so a later `shift` cannot turn 20 sessions into 20 non-missing observations.

### Intermediate values (not all are model inputs)

```text
P[t] = adjusted_close[t]
r[t] = P[t] / P[t-1] - 1
DV[t] = close[t] * volume[t]
```

`DV` is a dollar-trading-value proxy in USD/session. Both factors must use the same split basis. If price is divided by a split factor, matching volume is multiplied by that factor, preserving the product. Never use dividend-adjusted close in this calculation. If matching share bases cannot be verified, the dollar-volume feature is unavailable and the core readiness gate fails until resolved; do not substitute a mislabeled value.

For the volume-ratio feature, use volume normalized consistently for splits within the lookback. Log the normalization method. Do not silently use differently adjusted price and volume fields.

## 7. Feature rows and exact formulas

### Keys and validity fields

| Field | Type; role | Definition |
| --- | --- | --- |
| `dataset_version` | string; META | Input snapshot. |
| `instrument_id` | string; ID | Company security. |
| `as_of_date` | date; ID | Completed exchange session `t`. |
| `feature_set_version` | string; META | `core_v1` for the 16 inputs below. |
| `feature_cutoff_at` | UTC timestamp; META | Information cutoff used for the run, after close and bar arrival. Historical runs state an assumed after-close cutoff if actual availability is unrecorded. |
| `features_ready` | boolean; META | True only when all required inputs are finite, validated and timely. |
| `unavailable_reasons` | array of strings; META | Missing window, unknown adjustment or stale input reasons. |

All core features are float64 `X`, priority C. They use only data through session `t`. Require complete consecutive windows for each feature. Do not impute prices or shorten windows to hide gaps. The model uses only rows where the whole core feature set is ready.

Use `sample_std` with `ddof=1`; returns are simple decimal returns, not logs. A 60-return calculation needs 61 aligned closing prices. Use natural logarithm where `ln` appears. SPY returns `m[t]` come from its validated adjusted closes on the same sessions.

| Feature | Unit / allowed range | Exact definition at t | Required history |
| --- | --- | --- | --- |
| `ret_1d` | decimal, >= -1 | `P[t] / P[t-1] - 1` | 2 closes |
| `ret_5d` | decimal, >= -1 | `P[t] / P[t-5] - 1` | 6 consecutive closes |
| `ret_20d` | decimal, >= -1 | `P[t] / P[t-20] - 1` | 21 consecutive closes |
| `ret_60d` | decimal, >= -1 | `P[t] / P[t-60] - 1` | 61 consecutive closes |
| `vol_20d` | annualized decimal, >=0 | `sample_std(r[t-19:t]) * sqrt(252)` | 20 returns / 21 closes |
| `vol_60d` | annualized decimal, >=0 | `sample_std(r[t-59:t]) * sqrt(252)` | 60 returns / 61 closes |
| `downside_dev_20d` | annualized decimal, >=0 | `sqrt(mean(min(r[u],0)^2 for u=t-19..t)) * sqrt(252)` | 20 returns; include zeros for nonnegative returns |
| `max_drawdown_60d` | loss magnitude in [0,1] | For `u=t-60..t`, set `peak[u]=max(P[v], v=t-60..u)`; take `max(1-P[u]/peak[u])` | 61 closes, representing 60 return intervals |
| `price_sma20_ratio` | decimal, > -1 | `P[t] / mean(P[t-19:t]) - 1` | 20 closes |
| `price_sma50_ratio` | decimal, > -1 | `P[t] / mean(P[t-49:t]) - 1` | 50 closes |
| `rsi_14` | index points [0,100] | Wilder RSI on changes in adjusted close, defined below | At least 15 closes; preserve/reset state as specified |
| `volume_ratio_20d` | ratio, >=0 | `split_consistent_volume[t] / mean(split_consistent_volume[t-19:t])` | 20 volumes; denominator >0 |
| `log_dollar_volume_20d` | dimensionless log of USD-scaled amount, >=0 | `ln(1 + mean(DV[t-19:t]) / 1 USD)` | 20 validated matching-basis dollar volumes |
| `beta_60d` | dimensionless; may be negative | `sample_cov(r[t-59:t], m[t-59:t]) / sample_var(m[t-59:t])` | 60 paired stock/market returns; market variance >0 |
| `market_ret_20d` | decimal, >= -1 | `SPY_adjusted_close[t] / SPY_adjusted_close[t-20] - 1` | 21 benchmark closes |
| `market_vol_20d` | annualized decimal, >=0 | `sample_std(m[t-19:t]) * sqrt(252)` | 20 benchmark returns |

Intervals such as `[t-19:t]` are inclusive mathematical notation, not an instruction to use Python's exclusive slice endpoint unchanged.

### RSI implementation definition

For adjusted close change `delta[t] = P[t] - P[t-1]`, define `gain=max(delta,0)` and `loss=max(-delta,0)`. Seed average gain/loss with the arithmetic mean of the first 14 consecutive changes. Thereafter update each average as `(13 * previous_average + current_value) / 14`. RSI = `100 - 100/(1 + average_gain/average_loss)`.

If average loss is zero and average gain positive, RSI=100; if average gain zero and loss positive, RSI=0; if both are zero, RSI=50. A gap resets the state and requires a new 14-change warm-up. Carry correctly initialized state from each instrument's initial valid warm-up into its first usable feature row; do not compute centered or future-looking averages.

### Naming decisions and common errors

- No duplicate `momentum_20d`: its previously suggested percentage formula equals `ret_20d`.
- Downside deviation uses all 20 sessions with zero as its minimum acceptable daily return. It is not the standard deviation of only the negative observations.
- Drawdown is stored as a positive loss magnitude. A 30% drawdown is `0.30`, not `-0.30`.
- `market_*` refers to SPY in this version; do not silently swap in the S&P 500 price index.
- Raw price level, ticker, calendar date, future labels and screening outcomes do not enter the core model.
- `vol_20d=0.25` describes past annualized variability; it is not the same field as the unknown `future_volatility_20d` target.

### Split manifest

Store `split_version`, actual first/last feature dates, maximum label end, row counts, unique session counts, ticker counts and purge counts for `train`, `validation`, `test` and final `development_refit`. The required invariant is:

```text
max(label_end_date in earlier fitting/selection partition)
    < min(as_of_date in next evaluation partition)
```

A 20-session purge applies to all stocks on affected dates. No random row splitting and no future values in normalization, feature selection or imputers.

## 9. Optional market/macro context — priority E

Core forecasting can run without this record. Data source: FRED official series and vintage documentation (design S7).

| Field | Type / unit; role | Definition |
| --- | --- | --- |
| `series_id` | string; ID | `VIXCLS` or `DGS3MO`. |
| `observation_date` | date; RAW | Date the economic/market quantity describes. |
| `source_value` | float64; RAW | Original value, in the series' original units. |
| `source_unit` | string; META | `index_points` for VIXCLS; `annual_percent` for DGS3MO. |
| `vintage_date` | date or null; META | Source real-time/vintage date; distinguish first release and revisions. |
| `available_at` | UTC timestamp or null; META | Verified publication time, if available. |
| `available_from_session` | date or null; META | First permitted session cutoff after release, conservatively the next session if only a release date is known. |
| `source_url` | string; META | Series/retrieval source without secrets. |
| `retrieved_at` | UTC timestamp; META | Snapshot download time. |

Derived extension inputs:

- `vix_lagged`: latest eligible VIXCLS observation whose observation date is earlier than the feature date and whose availability is before the cutoff. Unit: index points, not a stock's realized-volatility percentage.
- `treasury_yield_3m_lagged`: latest eligible DGS3MO observation with the same timing rule, divided by 100. Thus `4.5` becomes `0.045` annual yield, not a daily or 20-day return.

Require both source-availability and vintage handling, not simply a join on observation date. Forward carry only a previously available observation, for at most five exchange sessions; then mark stale. If historical release/vintage timing cannot be established, leave this extension out or register a clearly qualified sensitivity experiment. A lag alone does not prove unrevised point-in-time data.

The main return target remains total return. Do not subtract an annual Treasury percentage directly from a 20-session return. Any later excess-return experiment must specify a matching-horizon conversion and a new target definition.

| `latest_balance_period_end` | S/E | Date of the coherent balance-sheet snapshot. |
| `ttm_period_end` | S/E | End of the latest completed compatible flow period. |
| `latest_available_from_session` | S/E | Latest publication-availability session among contributing facts. Must be <= feature/assessment date. |
| `fundamental_age_days` | S/E | Calendar days since the latest relevant reporting period end. |
| `evidence_complete` | S | True only when every needed business/ratio component is supported. |
| `missing_metric_names` | S/E | Array listing absent/ambiguous items; never silently filled with 0. |

Use a versioned **180-calendar-day maximum age** for core balance-sheet/financial screening evidence in this prototype, and review business disclosures at least annually with a **450-day maximum age**. These are Halalify freshness controls, not asserted standard thresholds. Older/missing evidence returns `needs_review` or `insufficient_data` and blocks portfolio eligibility. A current filing can still omit required income components; freshness alone is not completeness.

Possible SEC concept mapping starting points include `Assets`, `Revenues` or `RevenueFromContractWithCustomerExcludingAssessedTax`, `NetIncomeLoss`, `CashAndCashEquivalentsAtCarryingValue` and `AccountsReceivableNetCurrent`. They are examples for investigation, not a guaranteed mapping for every issuer. Debt and income-component extraction require explicit review. A broad investments or other-income tag cannot establish religious permissibility by itself.

TTM assembly requires four non-overlapping quarters. YTD Q2 minus YTD Q1 may yield the second quarter, and annual minus the first nine months may yield Q4, but use compatible statements, units, periods and availability dates and log the derivation. Do not take a later annual restatement back into an earlier information set.

### Optional `core_plus_fundamentals` feature definitions

| Field | Formula | Validity / unit |
| --- | --- | --- |
| `debt_to_assets` | `total_debt / total_assets` | Decimal; denominator >0, same balance period. |
| `cash_to_assets` | `cash_and_cash_equivalents / total_assets` | Decimal; denominator >0, reviewed no-overlap mapping. |
| `profit_margin_ttm` | `net_income_ttm / revenue_ttm` | Decimal, may be negative; revenue >0. |

If this extension is run, fit numeric imputation on training data only and add missingness indicators. Keep the raw missing values in storage. Imputation is permitted for an experimental predictor, never for asserting a screening pass. Report coverage and matched-row comparisons. Market capitalization and shares outstanding are not required for the selected asset-denominator profile or core model; add dated versions only if a later rule/feature explicitly needs them.

Each `rules` object contains `rule_id`, `numerator_metric`, `denominator_metric`, `value`, `operator`, `threshold`, `result`, and `evidence_fact_ids`. Numeric ratio values/thresholds use decimals. A zero/missing denominator gives an unknown result, never an automatic pass. Preserve the distinction between a known failure and unavailable evidence.

All four statuses can appear in the UI, but only `compliant` with the additional freshness/profile gates allows allocation. A known failing rule may establish rejection even when other inputs are absent. If no rule fails but data are absent, use `insufficient_data`; if interpretation or the rule profile awaits review, use `needs_review`. These application states prevent missing data from becoming false compliance claims.

Historical screening must use original available evidence and the registered rule edition. Applying a later rule specification retrospectively does not reconstruct official historical index membership. Do not apply today's company descriptions or verdicts to past portfolio dates without dated evidence.

Probability values must be finite and in [0,1], summing to one within 1e-6 for each task. They are estimated class probabilities, not guaranteed frequencies or probabilities of profit/loss. For an exact argmax tie, use the first class in the saved order. A deterministic historical baseline can return a class with null probabilities; do not invent confidence.

There is no `expected_return_percent` field in the classifier-first contract. A class or its probability cannot support that numerical claim. A future regression extension must add its own output, model, target definition and evaluation.

Keep future outcome storage separate from predictions despite overlapping names such as `return_class`: one is the observed answer in `target_rows`, the other is a forecast in `predictions`. A live request cannot include `future_return_20d`, `future_volatility_20d`, observed classes or future prices.

### Proposed API use

- `POST /v1/predict`: backend supplies instrument IDs and requested as-of date plus a dataset/feature reference, or the validated feature payload under an agreed transport. A typed schema accepts only declared fields. Backend does not send future outcomes.
- `POST /v1/screen`: backend supplies a dated fundamental snapshot/evidence reference and profile version. Return the assessment record with reasons.
- The AI service looks up preprocessing and label boundaries from the registered artifact, never recalculates them from a single live request.
- Backend stores returned prediction/assessment versions and exposes a user-safe response; credentials and model artifact locations remain internal.
- Bulk feature history can be Parquet internally; per-stock frontend responses can be JSON. The physical backend technology is still to be confirmed.

## 14. Data-quality behavior and necessary checks

| Situation | Required behavior |
| --- | --- |
| Same key, identical price record repeated | Deduplicate in normalized data and count it; preserve raw bytes. |
| Same key, conflicting price records | Quarantine and reconcile; never average them silently. |
| Missing daily price inside a rolling window | Feature/target unavailable until its required consecutive window is valid. |
| Final horizon outcomes not yet observed | Keep inference rows; exclude unfinished labels from supervised evaluation. |
| Unknown split/volume basis | Fail affected features and resolve adjustment evidence. |
| Historical report lacks availability date | Exclude from historical features/screening; current manual review remains possible. |
| Non-permissible income not reported | Unknown; never replace with zero to obtain compliance. |
| Current report revises earlier periods | Store new fact version with later availability; preserve earlier historical view. |
| Model input contains Y/PRED columns | Reject schema / fail leakage check. |
| Input order, units or feature version disagree | Reject the request; do not guess or reorder from display labels. |
| Required class cutoff not yet fitted | Model not ready; do not use sample illustration thresholds. |
| Prediction data stale | Return status and reason; do not show old results as fresh. |

Necessary implementation tests should use meaningful small fixtures: constant price path, a known 8% future return, a split/dividend event, a missing session, a filing released after its period end, an overlapping label boundary, a zero ratio denominator, and a probability/output-version check. These fixtures validate real failure modes rather than merely repeating the implementation.

For fresh scheduled forecasts, require the latest completed expected session's bar; if it is absent, return `stale_data`. A deliberately requested historical as-of date is not stale merely because it is old, but must satisfy the historical window/evidence rules.
